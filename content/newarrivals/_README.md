# 怎么录一条上新

一条上新 = 一个 JSON 文件。复制 `_template.json`、改文件名（下划线开头的会被跳过）、填内容即可，**不用重启服务**（每次请求现读）。

## 为什么是手工维护，而不是自动抓取

上新信息来自品牌官方公告、店铺页面、官方社交账号，这些都是**他人发布的内容**。自动抓取再展示，涉及转载授权和平台条款；而这个项目从第一天起就把"语料与内容只用于自用、不二次公开发布"写在了原则里。

所以设计成：**你看到一条上新，录一条**。工作量不大（一周几条），换来的是数据干净、来源可查、不会因为抓取被封。

## Baby 官网可以先生成草稿

Baby 官网是公开的 Shopify 商品目录，可以用脚本把官方字段抄成草稿，再人工确认：

```bash
python scripts/scan_baby.py --days 30            # dry-run：只列，不写
python scripts/scan_baby.py --days 30 --write    # 写 content/_drafts/newarrivals/
python scripts/scan_baby.py --list               # 看草稿
python scripts/scan_baby.py --approve <id>       # 确认一条，移进 content/newarrivals/
```

三条纪律：

1. **草稿不生效。** `load_newarrivals()` 只读 `content/newarrivals/`，草稿在 `content/_drafts/` 下，推荐页不会显示。
2. **发售日、风格、款式必须人工核对。** 脚本只从官方字段抄标题/价格/链接/图片/尺寸；`styles` 留空，因为风格是判断，不是官方字段。
3. **`--approve` 会先用正式的 loader 校验**：缺字段、日期不合法、id 重复都会被挡下来，草稿留在原处不移动。

## 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | 全局唯一。建议 `年份-月-品牌-系列`，重复会被跳过并在页面提示 |
| `brand` | ✅ | 品牌 id，和 `content/size/*.json` 里的 `brand` 保持一致，这样尺码助手能直接对上 |
| `brand_name` | | 界面显示名。不填就用 `brand` |
| `series` | ✅ | 系列名 |
| `release_date` | ✅ | `YYYY-MM-DD`。**推荐排序靠它算新鲜度，这个字段错了整条就不可信** |
| `price_range` | | 价格区间，写成字符串（"295 - 880"），不要写成数字 |
| `items` | | 包含哪些品类，如 `["JSK","SK","KC"]` |
| `styles` | | 风格标签，**只能从固定词表里选**：甜系 / 古典 / 哥特 / 蒸汽朋克 / 和风 / 日常 / 学院 / 中华风。写别的会被忽略，推荐页按它匹配用户偏好 |
| `image` | | 图片。三种填法：留空（显示占位）、外部 URL、或本地 `/media/xxx.jpg`（先调 `POST /api/media` 上传拿到地址） |
| `link` | | 原始链接，方便回查 |
| `note` | | 发售方式、配色、注意事项 |
| `source` | | **依据来源。空着界面会标"未标注来源"** |
| `sample` | | 示例数据置 `true`，页面顶部会显示醒目提示，避免把演示数据当真 |

## 两条容易忽略的

- **`release_date` 用发售日，不要用你录入的日期。** 用录入日期会让所有条目都"很新"，推荐页就失去意义。
- **`brand` 要和尺码表对齐。** 对齐之后，用户在推荐页看到某品牌上新，可以直接跳去算尺码——这是这两个页面唯一真正的连接点。
- **`styles` 是固定词表，不是自由标签。** 写「甜美」「甜」都不会匹配到偏好里的「甜系」。词表定义在 `app/domain/newarrivals.py` 的 `STYLE_OPTIONS`，要加新风格请改那里（改之前想清楚：分类轴一乱，推荐就不准了）。
